⚠️ 关键注意事项

GitHub API 管控

单 GitHub 账号每小时 API 调用限制 5000 次，需监控账号调用量，建议配置 3-5 个账号做负载均衡；定期轮换 Token，避免长期使用同一 Token 触发风控。

数据库运维

生产环境需开启 MySQL 主从复制，每日全量备份+增量备份；对部署记录、审计日志等大表做分表处理，避免单表数据量过大影响查询性能。

接口安全

生产环境需启用 HTTPS，对所有 API 接口添加频率限制（单 IP/用户每秒≤10 次）；AUTH_SECRET/ADMIN_SECRET 需定期更换，避免硬编码在代码中。

域名合规

备案域名需严格审核部署内容，避免违规内容导致域名被注销；临时域名需准备多个备用域名，建立一键切换机制。

🚨 潜在风险与应对策略

GitHub 账号封禁风险

多账号池共用 IP 可能被 GitHub 关联封禁，导致免费链路瘫痪。

应对策略：

  • 接入动态代理池，每个账号使用独立 IP 调用 API
  • 限制单账号每日部署次数（≤100 次）
  • 建立备用账号池，主账号封禁时自动切换

域名滥用风险

部署内容包含违规信息，导致域名被监管部门封禁，影响所有用户。

应对策略：

  • 接入第三方 AI 内容审计 API，部署前强制审核
  • 对试用用户部署内容添加水印，限制传播范围
  • 建立违规内容快速下架机制，10 分钟内处理投诉

成本失控风险

付费用户 OSS 带宽/存储超支，或试用用户刷 GitHub Pages 流量，导致成本超出预期。

应对策略：

  • 为每个用户设置流量/存储硬上限，超出自动暂停服务
  • OSS 开启流量监控告警，超阈值时推送通知
  • GitHub Pages 访问量异常时，临时限制该链接访问

数据安全风险

用户部署的 HTML 内容包含敏感信息，或数据库泄露导致用户数据外泄。

应对策略：

  • 对部署的 HTML 内容做脱敏处理，过滤敏感信息
  • 数据库敏感字段（如 Token）加密存储
  • 定期做安全渗透测试，修复漏洞
